# Вклад в NexRoute 🤝

Спасибо за интерес к проекту. NexRoute затрагивает системную сеть Windows, поэтому изменения должны быть воспроизводимыми и проверяемыми.

## 🚀 Процесс разработки

1. Создайте Fork репозитория.
2. Создайте ветку:

   ```bash
   git checkout -b feature/short-name
   # или
   git checkout -b fix/short-name
   ```

3. Вносите одно логически связанное изменение на Pull Request.
4. Запустите проверки:

   ```powershell
   pwsh ./scripts/Test-Repository.ps1
   ```

5. Для изменений сборки выполните ручной build workflow или локальную сборку.
6. Опишите влияние на Windows 10/11, upstream compatibility и лицензирование.

## ✅ Требования к Pull Request

- понятное название и описание причины изменения;
- список изменённых функций;
- способ проверки;
- отсутствие бинарников и архивов;
- сохранение совместимости с пользовательскими списками;
- обновление RU/EN документации при изменении пользовательского поведения;
- отдельное указание изменений сетевых стратегий или payload-файлов.

## ⛔ Не добавляйте

- `.exe`, `.dll`, `.sys`, `.bin`, ZIP/RAR/7z;
- пользовательские списки с реальными приватными данными;
- неподтверждённые бинарники из сторонних зеркал;
- стратегии без описания назначения и тестирования;
- изменения, скрывающие происхождение сторонних компонентов.

## 🧪 Тестирование сетевых изменений

Для изменения стратегии приложите:

- версию Windows;
- тип подключения и провайдера;
- результаты YouTube Web/Video;
- результаты Discord Web/CDN/Voice;
- влияние на обычные сайты и игры;
- состояние Game Filter и IPSet Filter;
- точную команду `winws` до и после изменения.

## 📝 Стиль

- Batch/PowerShell должны завершаться с корректным exit code;
- пути всегда заключаются в кавычки;
- ошибки должны быть понятны пользователю;
- UI-текст поддерживается на RU и EN;
- версия берётся из `.service/version.txt`;
- upstream baseline не меняется без отдельного PR.
